### 三、部署步骤及命令

#### 1. MySQL 安装与配置

```bash
sudo apt update
sudo apt install mysql-server -y
sudo service mysql start
# 设置 root 密码（与 Windows 开发环境一致）
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'qazwsx@123'; FLUSH PRIVILEGES;"
# 创建数据库
mysql -u root -pqazwsx@123 -e "CREATE DATABASE IF NOT EXISTS dingban_backend;"
# 开机自启
sudo systemctl enable mysql
```



#### 2. Redis 安装与配置

```bash
sudo apt install redis-server -y
sudo service redis-server start
# 测试
redis-cli ping   # 返回 PONG
# 开机自启
sudo systemctl enable redis-server
```



#### 3. Django 后端部署

```bash
cd ~/zhilian-platform/backend/django_react
# 创建虚拟环境
python3 -m venv venv
source venv/bin/activate
# 安装依赖（遇到 mysqlclient 编译错误）
sudo apt install pkg-config libmysqlclient-dev -y
pip install -r requirements.txt
# 数据库迁移
python manage.py makemigrations
python manage.py migrate
# 启动（必须用 0.0.0.0 才能外部访问）
python manage.py runserver 0.0.0.0:8000
```



**关键配置修改**：`settings.py` 中添加 `ALLOWED_HOSTS`：

```python
ALLOWED_HOSTS = ["localhost", "127.0.0.1", "192.168.0.120", "*"]
```

#### 5. 爬虫调度器部署

#### 6. React 前端部署

```bash

source ~/.bashrc

#### 7. Windows 端口转发

在 Windows PowerShell（管理员）中：

# 添加端口转发
netsh interface portproxy add v4tov4 listenport=8000 listenaddress=127.0.0.1 connectport=8000 connectaddress=192.168.0.120
netsh interface portproxy add v4tov4 listenport=8001 listenaddress=127.0.0.1 connectport=8001 connectaddress=192.168.0.120
# 查看
netsh interface portproxy show all
```
这样前端代码中的 `127.0.0.1:8000` 自动转发到 Ubuntu。

### 四、遇到的困难及解决思路

| 困难                               | 原因                       | 解决思路                                   | 命令                                                             |
| -------------------------------- | ------------------------ | -------------------------------------- | -------------------------------------------------------------- |
| `mysqlclient` 编译失败               | 缺少系统依赖                   | 安装 `pkg-config` 和 `libmysqlclient-dev` | `sudo apt install pkg-config libmysqlclient-dev -y`            |
| 外部无法访问 Django                    | 默认监听 `127.0.0.1`         | 改用 `0.0.0.0:8000` 监听所有接口               | `python manage.py runserver 0.0.0.0:8000`                      |
| `ALLOWED_HOSTS` 错误               | Django 安全限制              | 添加 Ubuntu IP 和通配符                      | 修改 `settings.py` 中 `ALLOWED_HOSTS`                             |
| Windows 无法连接 Ubuntu              | 可能防火墙拦截                  | 关闭防火墙测试；确认 Django 用 `0.0.0.0`          | `netsh advfirewall set allprofiles state off`                  |
| Node.js 版本过低                     | 系统自带 v12，Vite 需要 v20     | 用 nvm 升级 Node.js                       | `nvm install 20 && nvm use 20`                                 |
| Vite 外部无法访问                      | 默认只监听 localhost          | 加 `--host 0.0.0.0`                     | `npx vite --host 0.0.0.0`                                      |
| FastAPI CORS 报错                  | `.env` 文件覆盖了代码中的 CORS 配置 | 编辑 `.env` 添加 `192.168.0.120:5173`      | `sed -i` 修改 `CORS_ORIGINS`                                     |
| JWT 登录报错 `no attribute 'encode'` | `pyjwt` 与 `PyJWT` 版本冲突   | 卸载冲突包，装正确版本                            | `pip uninstall pyjwt PyJWT jwt -y && pip install PyJWT==1.7.1` |
| 头像不显示                            | Ubuntu 数据库无头像数据          | 在 Ubuntu 前端重新上传（只有一台服务器不存在此问题）         | -                                                              |
| `python` 命令找不到                   | Ubuntu 默认用 `python3`     | 激活虚拟环境后自动有 `python`                    | `source venv/bin/activate`                                     |
| `pipreqs` 生成失败                   | 文件有 BOM 头（U+FEFF）        | 手动创建 `requirements.txt`                | `echo fastapi > requirements.txt`                              |

### 五、核心思路总结

1. **保持配置一致**：MySQL 用户名、密码、端口与 Windows 开发环境一致，代码不用改
    
2. **0.0.0.0 vs 127.0.0.1**：对外服务必须监听 `0.0.0.0`，否则外部无法访问
    
3. **端口转发**：Windows 浏览器访问 `localhost` 自动转发到 Ubuntu，前端代码不用改
    
4. **虚拟环境隔离**：三个后端各自有 `venv`，依赖互不影响
    
5. **手动 CI/CD**：`git push` → `git pull` → 安装依赖 → 启动服务，理解自动化部署的底层原理
    
6. **单机 vs 多机**：开发阶段只有一台服务器时，不存在数据同步问题；多台服务器需要用云存储

#### 照片上传失败功能解决
1. 头像上传流程
		前端选择头像 → FormData组装 → axios发送 → 后端接收 → 保存文件 → 更新数据库

2.  后端日志显示json数据，没有收到avatar文件，原因是，在request。js 文件，在请求拦截器中添加了判断，如果是formdata，删除content-type 请求头，让axios自动设置
3. 头像文件被清空，控制台显示avatar文件为null，formdata中没有avatar字段，原因是每次user都更新充值头像，每次user对象变化时，调用getuserinfo（），useeffect都会执行，setavatar（null）。导致选择的头像文件清空，解决方案，一处不必要的setavatar（null），调用
4.  content-type覆盖，axios实例强制设置application/json，后端无法识别multipart/form-data
5. 头像被重置，useEffect每次user更新都清空avatar，用户选择的头像文件丢失
